### Название задачи:
Разработать концептуальную архитектуру MVP онлайн-выдачи кредитов с учётом обновлённых процессов по депозитам и передаче ставок в кол-центры

### Автор:
Технологический консультант по цифровизации бизнеса

### Дата:
27.10.2025

---

### Функциональные требования

| КОД | ТРЕБОВАНИЕ |
|-----|-----------|
| F1 | Подача заявки на кредит через сайт (для новых клиентов) с ФИО и телефоном |
| F2 | Подача заявки на кредит через интернет-банк (для существующих клиентов) с выбором суммы и СМС-подтверждением |
| F3 | Отображение актуальных ставок по кредитам на сайте и в интернет-банке |
| F4 | Персонализированные ставки и предодобренные предложения в интернет-банке |
| F5 | Автоматическая проверка скоринга при вводе паспортных данных на сайте |
| F6 | Единая заявка: сквозной ID заявки между каналами (сайт → отделение → АБС) |
| F7 | Уведомления по СМС о статусах заявки (одобрение, открытие и др.) |
| I2 | Внедрение централизованного справочника ставок (единый для депозитов и кредитов) |
| IF2 | Интеграция с Кредитным конвейером, скорингом, АБС, СМС-шлюзом, внутренним и партнёрским кол-центрами |

---

### Действующие лица и системы

| № | Действующие лица и системы | Use Case | Описание |
|---|----------------------------|----------|----------|
| 1 | Новый клиент, сайт | Подача заявки на кредит | Клиент вводит ФИО и телефон → заявка передаётся в Lead Management |
| 2 | Существующий клиент, интернет-банк | Подача заявки на кредит | Клиент указывает сумму → подтверждает СМС → заявка направляется в Credit Application API |
| 3 | Скоринговая система | Расчёт рейтинга клиента | Выполняется при вводе паспортных данных на сайте или при подаче заявки из интернет-банка |
| 4 | Внутренний кол-центр | Обработка заявок с сайта | Менеджер получает заявку и может предложить особые условия |
| 5 | Партнёрский кол-центр | Консультирование по ставкам | Получает файлы со ставками ежедневно |
| 6 | Бэк-офис кредитования | Ручная обработка заявок (MVP) | В рамках MVP — одобрение/отклонение заявки вручную через АБС |
| 7 | Клиент | Получение СМС | Уведомления о статусе заявки и одобрении кредита |

### Нефункциональные и архитектурно значимые требования

| КОД | ТРЕБОВАНИЕ |
|-----|-----------|
| R1, R3 | Доступность 99,9%, поддержка резервного ЦОД |
| R2, PH1 | Шифрование трафика (TLS 1.2+) и данных в покое |
| R4, DC1, P2 | Запрет прямой интеграции с АБС в реальном времени |
| U2 | Время отклика ≤200 мс для справочных данных (ставки, условия) |
| P1 | Горизонтальное масштабирование фронтенд- и вспомогательных сервисов |
| S2 | Использование знакомых технологий: Java, .NET, MS SQL, Oracle, REST |
| S3 | Модульность и возможность расширения (в т.ч. для будущей автоматизации) |
| DC2 | Текущая версия интернет-банка несовместима с Kafka → использовать REST/JMS/Service Broker |
| DC3 | Совместимость с существующими платформами разработки |

Вводится **единая архитектура онлайн-кредитования**, основанная на следующих компонентах:

### 1. **Справочник ставок (единый микросервис)**
- Реализован как микросервис на **Java Spring Boot + PostgreSQL**.
- Хранит ставки по **депозитам и кредитам**.
- Получает обновления от АБС/бэк-офиса **асинхронно** (REST/JMS).
- Предоставляет ставки:
  - Через **REST API** для сайта, интернет-банка и внутреннего кол-центра.
  - Через **ежедневные файлы (CSV/JSON)** для партнёрского кол-центра (SFTP/email).
- Поддерживает **кэширование** (Caffeine/Redis) для выполнения U2.

### 2. **Application API**
- Единая точка входа для заявок.
- Генерирует **сквозной ID заявки** (F6).
- Интегрируется с:
  - **Scoring Adapter** (для F5),
  - **Справочником ставок** (для F3, F4),
  - **Lead Management** (для заявок с сайта),
  - **Notification Service** (для F7).

### 3. **Lead Management**
- Приём и маршрутизация заявок с сайта.
- Интеграция с системой **внутреннего кол-центра** через REST.
- Поддержка ручной обработки менеджером (MVP).

### 4. **Scoring Adapter**
- Проксирует вызовы к **системе скоринга** и **Бюро КИ**.
- Выполняется **только при наличии паспортных данных** (F5).
- Результаты кэшируются для снижения нагрузки (P3).

### 5. **Credit Engine (Camunda)**
- Оркестрация бизнес-процесса кредитования.
- В MVP — **ручное одобрение** в АБС, но процесс уже описан в BPMN.
- Интеграция с АБС — **асинхронная** (через JMS или файлы), без прямых вызовов (DC1).

### 6. **Notification Service**
- Отправка СМС через существующий **СМС-шлюз**.
- Триггеры: одобрение, отклонение, уточнение данных.

## Обоснование выбора решения

| Вопрос | Обоснование |
|--------|-------------|
| Почему единый справочник ставок? | Унификация с депозитами (ADR от 26.10.2025), устранение Excel, поддержка I2 |
| Почему микросервис на Java? | Экспертиза в команде АБС и кол-центра (S2), совместимость с Camunda и скорингом |
| Почему не Kafka? | Ограничение DC2 — интернет-банк не поддерживает Kafka на текущем этапе |
| Почему асинхронная интеграция с АБС? | Требования R4, P2, DC1 — защита перегруженной АБС |
| Почему Camunda? | Уже используется в кредитном конвейере, поддержка BPMN, внутренняя экспертиза |

## Альтернативы

| Альтернатива | Недостатки |
|--------------|------------|
| Использование Kafka на MVP | Технически невозможно из-за ограничения интернет-банка (DC2) |
| Полная автоматизация выдачи кредита на MVP | Противоречит бизнес-плану: MVP предполагает ручную обработку бэк-офисом |

---

## Недостатки, ограничения, риски

| Риск | Митигация |
|------|-----------|
| Задержка актуализации ставок (раз в сутки) | Приемлемо для MVP; в будущем — переход на событийную модель |
| Дублирование данных между АБС и микросервисами | Временное решение; сквозной ID (F6) обеспечивает согласованность |
| Зависимость от ручной обработки в бэк-офисе | Соответствует текущему этапу MVP; автоматизация — на следующем этапе |
| Нагрузка на скоринг при массовых заявках | Кэширование и триггер только при полных данных (P3) |
