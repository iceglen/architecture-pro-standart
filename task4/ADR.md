### **Название задачи:**
Обеспечить доступ внутреннего и партнёрского кол-центров к актуальным ставкам по депозитам в рамках MVP по цифровизации депозитных продуктов.

**Дата:**

### Функциональные требования

| КОД | ТРЕБОВАНИЕ |
|-----|------------|
| F3  | Отображение актуальных ставок по депозитам на сайте и в интернет-банке |
| I2  | Внедрение централизованного справочника ставок с доступом для бэк-офиса депозитов и кредитов |
| IF2 | Интеграция с системой кол-центра и партнёрским кол-центром |
| R2, PH1 | Защита персональных и финансовых данных при передаче и хранении |

---

### Действующие лица и системы

| № | Действующие лица и системы | Use Case | Описание |
|---|----------------------------|----------|----------|
| 1 | Бэк-офис, АБС | Обновление ставок | Сотрудники бэк-офиса обновляют ставки ежедневно; данные поступают из АБС или Excel и затем загружаются в централизованный справочник |
| 2 | Внутренний кол-центр | Получение ставок через API | Операторы кол-центра получают актуальные ставки в реальном времени через REST API микросервиса |
| 3 | Партнёрский кол-центр | Получение ставок через файлы | Партнёрский кол-центр получает ежедневные файлы со ставками (CSV/JSON) через SFTP/email |
| 4 | Сайт / Интернет-банк | Отображение ставок | Фронтенд-системы получают ставки через тот же REST API микросервиса |

---

### Нефункциональные и архитектурно значимые требования

| КОД | ТРЕБОВАНИЕ |
|-----|------------|
| R4, DC1, P2 | Запрет прямой интеграции с АБС в реальном времени — ставки должны поступать асинхронно |
| U2 | Время отклика API меньше 200 мс — требуется кэширование |
| R1, R3 | Доступность 99,9%, поддержка резервного ЦОД |
| S2 | Использование знакомых технологий: Java, PostgreSQL, REST |
| PH1 | Шифрование данных в движении (TLS 1.2+) и в покое |
| DC3 | Совместимость с существующими платформами разработки |
| S3 | Поддержка модульного расширения (в будущем — кредиты, валютные ставки и т.д.) |

Вводится новый **микросервис «Справочник ставок»**, реализуемый внутренней командой на Java Spring Boot с PostgreSQL в качестве СУБД.

### Основные функции сервиса:
- Хранение и управление актуальными ставками по депозитам (в будущем — и по кредитам).
- Приём обновлений ставок от АБС/бэк-офиса **асинхронно** (через REST или JMS, в зависимости от готовности АБС).
- Предоставление ставок через **REST API** для внутренних систем: сайт, интернет-банк, внутренний кол-центр.
- Ежедневная **генерация файлов** (CSV/JSON) для партнёрского кол-центра.
- Поддержка **кэширования** (например, через Caffeine или Redis) для обеспечения U2.
- Обеспечение **сквозной безопасности**: TLS 1.2+, шифрование БД, аутентификация вызовов.

### Интеграции:
- **Источник данных**: АБС → микросервис (асинхронно, без нагрузки на АБС).
- **Потребители**:
  - Внутренний кол-центр — REST API (`GET /api/v1/deposit-rates`).
  - Партнёрский кол-центр — файлы через SFTP/email (шифрованные при необходимости).
  - Сайт и интернет-банк — тот же REST API.

## Обоснование выбора решения

**Почему отдельный микросервис, а не расширение АБС или Excel?**
- Соответствует требованию **I2** — централизованный справочник.
- Устраняет зависимость от Excel и ручных процессов.
- Позволяет **изолировать АБС** от нагрузки (**R4, P2, DC1**).
- Поддерживает **оба сценария**: API для внутренних систем и файлы для партнёров.

**Почему Java + Spring Boot + PostgreSQL?**
- Экспертиза уже есть в команде АБС и кол-центра (**S2**).
- PostgreSQL используется в системе кол-центра → упрощает сопровождение.
- Поддержка микросервисной архитектуры и горизонтального масштабирования (**S3, P1**).

**Почему не Kafka?**
- Текущая версия интернет-банка несовместима с Kafka (**DC2**).
- Для MVP достаточно REST + файлов; Kafka может быть внедрена на следующем этапе.

---

## Альтернативы

- **Хранение ставок в АБС + прямой REST-доступ**: нарушает **DC1, R4, P2**.
- **Ручная рассылка файлов из Excel**: не масштабируется, нарушает **I2, R1, U2**.

---

## Недостатки, ограничения, риски

- **Задержка актуализации ставок**: если АБС обновляет ставки раз в сутки, кол-центр будет работать с данными сутковой давности.

- **Дублирование данных**: ставки будут храниться и в АБС, и в микросервисе.

- **Зависимость от процесса загрузки из АБС**: если АБС не сможет отправлять обновления, потребуется ручной импорт.
